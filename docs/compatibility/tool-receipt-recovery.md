# 工具回执保留与恢复

领取、创建、提交等操作的成功回执是后续办理依据。上下文裁剪只影响模型看到的正文，不能要求重新执行有状态操作找回旧结果。

## 运行机制

- `ActionNode.completeBatch` 从已完成事件保存原文，按工具调用标识建立本轮索引。原文不可覆盖，索引随批次更新；当前工作集引用最多八条真实回执，再补最近八条，正文展示上限不影响索引内容。
- 有归档回执时执行事实提示提供 `receiptIndexPath`。已知 `resultRef` 可直接读取；否则通过既有 `read_file` 按游标分页读取分行、近期优先的索引。参数仅存脱敏预览，目录不重复存正文，结果摘要不代替完整原文。
- 不超过 512 字符的旧回执直接保留；长回执在年龄压缩及预算裁剪前保存为文件引用。落盘失败时保留原文，并防止后续软裁剪、清理和摘要预处理将未保存的业务回执丢弃。
- 普通读取工具沿用原始文件入口，避免读取结果再落盘的递归；技能原文另按实际调用归档以保留版本。`returnDirect` 的正文和调用参数不进入恢复索引。
- 已恢复的 `read_file` 正文不再仅按响应年龄重新缩为路径，避免模型反复展开已经读过的材料；整体历史预算、去重与摘要仍生效。读取不产生嵌套归档，也不缓存实时业务查询。
- 摘要模型采用独立输入预算。超预算观察先按本输入与摘要批次保存完整快照，再发送有省略标识的片段及工作集、真实事实；快照不生成工具成功记录。该投影不改变主推理历史中的读取正文。归档失败时保护观察原文；摘要失败时保留交接依据及恢复入口，不能只保留前 500 字符。
- 进行中或受阻步骤的 `progress_update.note` 展示最多 512 字符，记录实际返回标识、请求标识、已完成项和下一步。调用成功不等于整个办理步骤完成。
- 用户显式发起新一轮操作时建立独立台账，正常执行；不缓存同参数的业务调用，不拦截新的授权操作。

恢复路径复用 `ToolResultStorage` 的目录、成员隔离、会话删除和保留期策略，不新增接口、表、后台任务或质检业务状态。

## 开发验证

`ActionReceiptRecoveryIntegrationTest` 使用真实执行节点、执行器、回执文件和 `read_file`，业务服务使用计数回调：领取一次 → 连续取证 30 次 → 裁剪历史 → 读取索引和原文 → 两项各提交一次。随后同一会话显式新一轮领取仍执行且使用独立索引。补充测试覆盖不可覆盖原文、索引更新、会话隔离、存储失败、短回执、成员目录和直接返回边界。

上述测试属于研发本地回归。另已完成第八轮真实模型质检及两次原任务跨重启续办，证据见[验证记录](agent-context-runtime-verification.md)；其结论限于已记录场景。真实模型仍需按照回执恢复提示和技能要求推进业务。

## 后续优化建议（2026-10-14 保留）

结合真实复跑确认的问题，后续范围、实施批次与验收指标见[Agent 基础能力优化实施计划](agent-context-runtime-optimization-plan.md)。优化对象为通用运行时，案件质检仅作为验证场景；业务完成条件与推进顺序由技能负责。

当前方案采用短回执保留、原文外置、按需恢复和进度摘要。本轮进一步实现分页目录、工作集引用、材料复用提示、SSE 恢复、完成保留期及隔离产物/检查点，摘要独立预算和最终请求内相同读取正文去重也已接入。第八轮同参数质检完成，两次原任务跨重启续办零重新领取；第八轮输入较原基线下降 14.6%、工具调用下降 11.4%，属于单样本观察，模型等待不参与性能验收。验收优先保障可靠性、稳定性和可恢复性，不设置固定效率或 token 降幅门槛。导致恢复往返增加的正文年龄压缩实验已撤回，后续保留按步骤组织证据及来源统计建议。实际范围和验证状态以实施计划及真实对照记录为准。业务推进与完成判定仍由技能维护。

| 维度 | 当前优势 | 当前不足 |
| --- | --- | --- |
| 数据完整性 | 普通业务回执保存原文，摘要遗漏后可恢复 | 原文存在不保证模型及时找到并使用 |
| 上下文成本 | 长结果使用文件引用，减少重复发送全文 | 恢复通常需要先读索引再读原文，增加调用和等待 |
| 办理衔接 | 保留标识、请求 ID 和下一步 | 备注是自由文本，推进仍依赖模型，缺少可验证的完成条件 |
| 通用性 | 不依赖案件质检字段 | 工具成功不能直接证明业务步骤完成 |
| 工程成本 | 复用现有存储和账本 | 索引随每批完整重写，大规模调用时有额外读写开销 |

容量规则不能直接代表业务重要性。当前工作集引用的早期回执优先于普通近期查询结果保留，未展示部分仍可恢复。

### 与常见上下文管理模式的取舍

| 模式 | 适用用途 | 局限与使用边界 |
| --- | --- | --- |
| 滑动窗口 | 保留近期交互，控制上下文成本 | 会遗忘早期关键事实，不单独承担办理状态保存 |
| 滚动或分层摘要 | 保留目标、决策、过程和交接 | 摘要有损，不能作为原始业务回执的替代 |
| 原文归档与按需读取 | 精确保留工具回执和证据 | 需要正确定位原文，恢复有调用开销 |
| 检索式记忆或 RAG | 从大量规范和知识资料查找相关内容 | 业务标识和提交状态需要精确定位，不能依赖语义近似命中 |
| 结构化状态与执行检查点 | 记录未完成项，支持中断续办 | 需要明确状态与完成条件，优先复用已有账本 |
| 提示词缓存 | 降低重复前缀的成本和延迟 | 不增加有效上下文，不保证业务办理完成 |

### 迭代顺序与验收依据

1. **可靠恢复入口与生命周期。** 修复回执索引分页、SSE 断线恢复、完成后保留时间与默认产物隔离，先补齐真实运行暴露的基础缺口。
2. **有界当前任务工作集。** 保存目标、约束、当前步骤、待办、下一步及真实证据引用；模型进度和工具执行事实分别维护，不推测业务状态。
3. **按步骤选择上下文和复用材料。** 当前步骤引用的早期回执优先保留，规范与工具说明按来源和版本复用，实时查询按需要执行，避免重复正文进入多个提示位置。
4. **跨轮续办检查点。** 复用现有存储恢复目标、待办、执行事实和原文引用，明确继续与新任务，恢复上下文不自动重放历史操作。
5. **多场景效率验证。** 用固定回执回放查询分析、文件处理和包含副作用的长流程，比较上下文装配、归档、恢复、证据及 token 消耗；另做真实模型端到端完整性验证。模型响应等待单列且暂不计入性能验收，案件质检是其中一个真实样本。

优先实施顺序为基础可靠性、上下文组织与材料复用、跨轮检查点和通用验收。批次完成判定及领取/提交顺序留在技能层，本轮基础实施不内置这些规则。新增接口、表、后台任务或恢复分支须有实际场景支撑，并在实施前核对现有台账和存储是否已提供相应能力。
