# Agent 基础能力优化实施计划

日期：2026-10-14。状态：本轮通用基础能力在已验证范围内完成实施、部署及可靠性验收；最终提交快照后端 23 套件 132 项、前端 3 套件 11 项全部通过。两次原任务中断续办及第八轮同参数质检完整通过。三类固定轨迹各预热 5 次、采样 30 次通过。输入比原基线下降 14.6%、工具调用下降 11.4%，但输入成本高于第六轮；该单样本只作为辅助观察。模型等待不计入性能验收，不设固定效率或 token 降幅门槛。按步骤选择正文、来源统计及成对性能对照保留为后续效率深化，不列为本轮可靠性验收阻塞；恢复边界见验证记录。交付范围为通用 Agent 运行时；案件质检是验证场景之一。

## 目标和职责

目标：长任务在上下文压缩、连接断开及跨轮继续后，仍能准确找到已执行结果、保留当前目标和下一步，并减少重复读取、模型空转和产物覆盖。

基础层负责执行事实、证据定位、上下文预算、连接生命周期、产物目录和恢复检查点。技能负责业务状态含义、业务完成条件和办理顺序。基础层提供可引用事实和扩展入口，不内置“领取后必须提交”等业务规则，不从普通 JSON 的字段名猜测业务状态。

现有短回执、原文外置和只读恢复机制继续使用。模型进度备注、工具执行状态、业务结果分别呈现：工具返回成功并不自动证明业务完成。

## 第一批：修复恢复入口和生命周期

### A. 可完整读取的工具回执目录

位置：`ActionExecutionLedger`、`ToolResultStorage`、现有 `read_file` 和恢复提示。

- 目录按回执分行组织，近期记录优先。每条保留调用标识、工具、时间、执行状态、原文路径和有界参数定位信息；完整参数和结果按现有隔离要求保存。
- 不将 `read_file` 返回的整段内容再次收进恢复目录摘要；执行审计仍记录实际读取。去除嵌套 JSON 及重复正文造成的目录膨胀。
- 每轮事实保留可直接使用的结果引用，已知调用标识或路径时直接定位原文，减少先读全目录再读文件的往返。
- 单条记录大小与分页响应按最终序列化结果约束，覆盖中文及 JSON 转义。截断时提供可继续读取的游标，不把目录截断当成结果不存在。
- 原文归档失败时保护现有正文；不得通过重新执行有副作用操作恢复回执。

验收：100KB 以上、多页目录的首、中、尾结果都能找回；没有单条超过读取上限的记录；原文保持完整；恢复不触发原工具。

### B. SSE 连接恢复和完成后保留期

位置：`ChatController`、`ChatStreamTracker`、前端 `useStream.ts`、`useChat.ts`。复用现有状态查询、重连及事件 ID 去重。

- 未收到任务结束事件便出现 EOF 或网络断开时，查询当前会话状态。仍运行则重订阅；已经完成则加载持久化消息；失败则显示真实失败原因。
- 恢复只订阅或查询，不重新发送用户指令，不启动新运行。主动停止、离开视图或切换会话不触发恢复拉回。
- 自动恢复采用有界退避，初始建议 1、2、4、8 秒、最多 4 次；每会话只允许一个恢复过程，耗尽后保留手动恢复入口。
- 完成后保留期从最后一个运行段完成时间起算，运行中空闲清理与已完成保留期分别判断；队列续跑不被上一段完成时间提前清理。
- 第一批允许连接按现有预算到期后恢复，不依赖延长超时。统一超时配置在有观测需要时再处理。

验收：12 分钟以上的模拟任务、执行中断线、最终结束事件前后断线均能呈现最终结果；运行启动次数始终为 1；完成后 5 分钟内可以回放；过期后可以查询持久化消息。

### C. 通用运行产物目录

- 基础运行环境提供 `artifactRoot`，按成员/工作区、会话和运行轮次隔离，优先复用已有目录与路径守卫。
- 技能和脚本将默认生成的报告、数据及过程文件放到本轮目录，生成文件展示使用相同路径。
- 用户明确指定的共享输出位置按原授权执行；工作区本身不改为完全隔离，避免破坏正常共享文件操作。
- 运行元数据记录归属及引用，业务报告字段仍由技能定义；原产物不批量迁移。

验收：两会话并行生成同名报告及同会话新一轮执行，默认产物互不覆盖；生成文件可展示；成员隔离不减弱；用户指定共享路径仍按要求写入。

第一批实施顺序：B → A → C，每项独立定向验证，再进行测试实例验收。

## 第二批：优化每轮上下文组织

### D. 当前任务工作集与原始执行事实分开保存

复用进度台账、执行台账与预算器，建立有界的当前任务工作集：当前目标、用户约束、当前步骤、待办、所引用回执与下一步。

- 模型或技能可更新目标、步骤和待办，这些内容是计划或判断；只有真实工具执行事件可以生成执行事实。
- 引用必须能定位到本会话/执行范围的真实回执；未知标识不被当成已执行证据。
- 上下文装配优先保留当前步骤引用的早期结果，其他长材料使用来源、短摘要和原文路径。引用关系也受预算约束，分页保留可定位入口。
- 不自动解析案件编号、领取明细或提交状态。技能需要结构化业务完成判定时，可使用通用引用能力自行声明，不纳入本轮基础实现。

验收：同一任务插入 30 次以上工具调用并强制压缩后，当前目标、待办和早期证据引用仍可恢复；模型不能用进度文字伪造执行成功。

### E. 静态材料复用与按步骤提供证据

- 技能文档、工具说明按来源及版本/内容标识记录已读状态，同一运行中的相同材料复用；普通文件和业务状态查询不被全局缓存或跳过。
- 文档正文保留可读取原文，提示中优先使用当前步骤需要的内容与精确引用。改版或新问题需要完整原文时正常读取。
- 同份文档先以工具结果出现、后以回执摘要再次出现的重复正文只在一个权威位置装配，其余位置使用引用。
- 按目标、当前步骤、引用材料、近期交互组织预算；保持用户指令、系统约束与工具调用/响应配对完整。
- 摘要保存决策和未完成工作，原文保存证据；摘要不替代原回执。进度提醒基于实际步骤变化，减少同内容催促。
- 在现有上下文统计中记录重复材料占比、各来源大小及恢复往返次数；稳定前缀只作为提示缓存优化候选，效果单独测量。

验收：不变的技能文档和工具说明不发生无原因重读；材料改变后能获得新版；实时查询按任务需要实际执行；压缩不丢失引用及工具配对。

### F. 回执精确检索的实施决策

第一批先使用分行目录和直接引用。第二批若通用长任务仍需扫描多页才能定位，新增一个本地只读回执查询工具，复用现有台账及文件，支持精确调用标识、工具和轮次过滤、分页及正文范围读取。

新增工具的证据依据是本轮已出现的 82KB 目录截断和后续多页定位成本；是否需要以第一批验证结果决定。结果查询受当前成员/工作区/会话边界约束。不新增 HTTP API、数据库表或语义向量库，也不同时维护两套原文存储。

## 第三批：跨轮检查点与通用验证

### G. 保存可解释、可定位的续办检查点

- 保存目标、用户约束、当前工作集、执行事实索引、原文引用和产物归属；优先复用现有会话存储及文件体系。
- 第一阶段支持迭代上限或用户中断后继续同一任务；继续与显式新任务分别建立执行范围。
- 恢复重建上下文，不自动重放历史工具。执行已发出而回执未知的情况标为待确认，由工具/技能既有协议确认；不推测成功或失败。
- 服务重启续办单独验证持久化、文件保留期、路径可访问性及外部会话有效期。尚未验证的恢复范围明确展示。
- 先覆盖实际中断场景；没有实际证据时不扩展成通用事务引擎、业务状态机或后台补偿系统。

### H. 多种场景对照验收

至少使用以下三类流程，避免只针对一个业务优化：

1. 查询与分析：多工具查数、读取大结果、压缩后引用早期证据并生成报告。
2. 资料与文件处理：加载技能和规范、多文件分析、并行会话产物及版本变化。
3. 包含副作用的长流程：使用模拟服务执行有状态操作、中断、恢复和结果待确认；案件质检可作为真实补充场景。

基础层采用固定回执及模拟模型重复回放，比较中位数和范围，并核对恢复事实与调用配对。真实模型复跑验证业务完整性；需要得出稳定效率收益结论时，再在相同模型、运行参数、数据及材料条件下至少运行 3 次。模型等待单列；模拟服务固定响应，真实业务复跑按测试环境或用户安排执行。

硬指标：真实工具事实与结果引用正确率 100%；恢复导致的副作用操作重放为 0；上下文恢复不丢当前目标与必要证据；前端断线恢复不启动额外运行；默认产物跨会话覆盖为 0。

验收优先级按用户最新要求调整为：可靠性、稳定性和可恢复性优先，在此基础上减少重复读取、模型空转及输入 tokens。不设置整体效率提升 30% 或输入 tokens 下降 50% 的硬门槛，也不为了达到降幅丢弃必要证据或弱化恢复能力。模型响应等待先不计入性能验收，总墙钟只记录；单列模型调用区间、工具与上下文装配耗时，无法完全扣除工具内部模型等待的剩余耗时标记为未完全归因。案件样本的 105 次工具调用只作参考，不作为所有业务的固定上限。

单列模型调用数、恢复读取数、重复读取数、摘要耗时、缓存命中和业务完整性。模型供应端延迟变化不归因于基础实现；减少取证或省略必要步骤不能计作优化成果。

### 稳定评估方法（按最新反馈调整）

分两层评估。基础层使用固定回执的录制回放，将同一工具轨迹交给真实执行节点、压缩器和请求装配器，模型返回固定结果，不访问生产业务。覆盖查询分析、文件处理、带副作用的长流程；每类至少三次，先预热再报告装配、归档和恢复的中位数及 P95，同时核对请求 tokens、完整证据、调用配对、原历史不变、未知回执不重放。前后版本用同一轨迹、同一窗口和同一机器成对比较，不要求模型自由选择完全相同的轨迹。

真实模型层保留端到端质检验证，以完成率、重复副作用、恢复往返及累计 tokens 为主要结果；冻结版本后同模型、同参数、同材料至少三次，报告中位数和范围。真实后端调用需要交错前后版本，避免时间段差异系统性偏向某一版本；测试不足时明确只获得单样本。模型及图像工具中的模型等待单列，不能分离的剩余时间不当作纯基础层耗时。单独测试相同模型请求的响应延迟只能评估供应端波动，不作为运行时优化收益。

## 实施和交付方式

每批按“实现 → 定向测试 → 简洁性复核 → 测试实例验收 → 指标比较”交付，通过后再扩大范围。最终运行配置冻结后执行完整场景验收。

- 工作区已有其他任务的未提交变化，实施时保护这些内容，只提交本批明确修改。
- 新增或实质修改 Java 声明遵循中文 JavaDoc 要求，生产及测试代码一致。
- 新增状态、接口、后台任务、迁移和恢复分支逐项对应实际需求或失败证据，移除无依据路径。
- 新工具、目录变量和检查点格式同步提示、技能接入说明、工具注册和测试；基础运行时不依赖某个业务技能已安装。
- 每批记录实际变更、测试命令、结果、可恢复范围与回滚边界。研发本地验证与真实模型验证分别陈述。
- 本计划不包含案件审核规则调整、业务批次状态机或强制领取/提交顺序；这些由相应技能独立演进。

## 后续效率深化建议

真实运行中摘要节点曾一次接收约 19 万至 21 万字符的观察集合。摘要独立预算和最终请求内相同读取正文去重已经实施，以下建议保留为后续效率深化；每项收益需有对照证据，核心恢复要求继续优先。

1. 持续评估已实施的摘要独立预算：保留目标、步骤变化、真实调用标识、未确认调用及原文入口，归档失败的正文继续保护。用实际模型请求和完整任务累计成本判断收益，不以摘要字符数缩短直接推断成本下降。
2. 在现有工作集内按当前步骤选择证据正文，明确稳定材料与新增取证的位置，避免同份材料在历史、工作集和摘要输入重复出现。选择依据采用真实来源和模型/技能声明的引用，不猜测业务字段，不重新引入恢复正文年龄裁剪。
3. 将模型等待、摘要调用、恢复读取、提示正文及缓存命中分开统计；三类通用固定场景重复验证核心恢复行为，补充同参数真实质检。效率对照报告实际变化与波动范围，不设置固定百分比门槛，不以单次样本宣称稳定收益。

### 摘要输入预算迭代（第七、八轮已实测）

已实施 `ObservationSummaryInput` 和摘要节点接入。`mate.agent.graph.observation.summary-input-max-tokens` 默认 12000，按模型窗口保留输出空间；预算包含摘要系统提示、原目标、当前进度工作集、真实执行事实及上一阶段摘要。完全相同观察只复用正文，实际轮次仍保留；超预算时先通过既有存储保存独立观察快照，再按轮次提供有界首尾片段并标注省略。原推理历史及 `read_file` 正文不因此缩为路径，不重启第三至第五轮的年龄裁剪实验。

快照按会话、原输入及实际摘要批次区分，使用既有成员隔离和保留期；它是观察来源，不成为新的工具执行成功事实。归档失败时保留原观察，可能超过软预算，明确记录；不丢正文来制造预算达标。摘要失败的降级保留目标、工作集、事实及恢复入口，替换原有前 500 字符降级。关键目标和事实本身超预算时同样保留并通过输入统计暴露，不能承诺任何大小的不可分目标都能装入窗口。

本次简洁性复核：新观察快照直接对应实测 21 万字符摘要请求及 500 字符降级丢交接信息；不增加接口、表、迁移、后台恢复或业务状态。预算器只装配摘要请求，不改用户模型、思考参数、取证要求或执行次数。请求捕获回归和同参数实测已完成；局部投影缩短不作为整任务效率收益证据。

第八轮完成后：保留摘要独立预算以约束已观测的大摘要请求；实际约 20 万字符观察投影为 7000 tokens、其余提示预算 4998 tokens，未出现第七轮的 88 次代码打印往返。本轮输入仍高于第六轮，不能证明摘要预算单独改善整体成本。后续若继续评估效率，固定同一轨迹成对回放各版本，再对冻结版本做多次真实样本；这些辅助评估不阻塞已验证范围内的可靠性验收。
